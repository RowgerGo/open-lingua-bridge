## PROJECT CONSTRAINTS

- Platform target: macOS and Windows only. No Linux, mobile, or Web target in MVP.
- MVP is local-first. Python Model Service is local sidecar or external local service.
- Do not default to cloud model services.
- Tauri handles UI, settings, status display, diagnostics, user interaction.
- Rust Core handles audio capture/output, routing, realtime scheduling, session state, IPC, performance-sensitive paths.
- Python Model Service handles VAD, ASR, machine translation, and TTS.
- MVP does not install or ship a self-developed virtual audio driver.
- Users are expected to configure third-party virtual audio devices when needed.
- Recording, transcription text, and translation text are not saved by default.

## API AND PROTOCOL RULES

- Ordinary control APIs use only `GET` and `POST`.
- `GET` parameters go in query params, for example `?a=1&b=2`.
- `POST` parameters go in JSON bodies.
- Do not introduce `PUT`, `PATCH`, or `DELETE` in MVP API docs or implementation.
- Rust/Python realtime channel is `WS /ws/session`.
- WebSocket text frames carry control messages, small results, status, and errors.
- WebSocket binary frames carry audio input and TTS audio output.
- Do not put realtime audio payloads into GET/POST JSON.
- Do not Base64-encode large audio payloads into JSON.
- All Rust/Python protocol messages include `protocol_version`.
- Binary frame layout uses magic `OLB1`, `header_len` as little-endian `u32`, UTF-8 JSON header, then payload bytes.
- MVP audio input recommendation: `pcm_s16le`, 16 kHz, mono.
- `segment_id` is generated by Rust Core Segment Scheduler and flows through ASR, translation, TTS, and playback.
- `asr.final` and `translate.result` for the same `segment_id` are accepted once in MVP.
