# AI 实时通话翻译工具需求文档

## 1. 项目概述

本项目旨在开发一款面向 macOS 和 Windows 的 AI 实时通话翻译工具。用户与外国人进行语音通话时，工具能够实时捕获双方语音，将对方语音识别、翻译并以本方语言展示或播报，同时将用户语音识别、翻译并通过语音合成输出为对方可理解的语言。

技术栈约束：

- Rust：核心音频采集、虚拟音频路由、实时调度、跨进程通信与性能关键路径。
- Python：ASR、机器翻译、TTS 等模型后端服务。
- Tauri：桌面端 UI、设置面板、状态展示和用户交互。
- 平台：仅支持 macOS 与 Windows，暂不支持 Linux、移动端和 Web 端。

## 2. 产品目标

### 2.1 核心目标

- 在通话场景中提供低延迟、双向、可理解的语音翻译能力。
- 支持用户选择输入设备、输出设备和虚拟音频设备，适配常见通话软件。
- 在 UI 中清晰展示实时识别文本、翻译文本、当前语言方向、延迟、模型状态和音频路由状态。
- 支持本地模型与云端模型两种后端模式：ASR 和 TTS 需要支持加载本地模型，也需要允许用户配置云端模型。

### 2.2 MVP 目标

MVP 版本优先验证端到端链路：

1. 捕获本机麦克风语音。
2. 捕获对方通话音频或系统输出音频。
3. 对两路音频分别进行 ASR。
4. 根据语言方向进行翻译。
5. 将翻译结果进行 TTS 合成。
6. 将合成音频输出到指定设备或虚拟麦克风。
7. 在 UI 中展示实时字幕、链路状态和基础设置。

## 3. 目标用户与场景

### 3.1 目标用户

- 需要与外国客户、同事或朋友进行语音沟通的用户。
- 需要在远程会议、电话销售、客服、在线教育等场景中进行跨语言沟通的用户。
- 希望在本地设备上运行翻译能力、减少隐私暴露的用户。

### 3.2 典型场景

#### 场景 A：跨语言电话沟通

用户使用 Zoom、Teams、Discord、微信语音或其他通话软件与英语使用者沟通。工具监听双方语音：

- 对方英文语音被识别并翻译为中文。
- 用户中文语音被识别并翻译为英文。
- 英文 TTS 通过虚拟麦克风送入通话软件，让对方听到翻译后的语音。
- 中文翻译可通过字幕或本机扬声器播放给用户。

#### 场景 B：会议辅助字幕

用户只需要理解对方语言，不需要把自己的声音翻译给对方。工具仅捕获系统音频，实时展示本方语言字幕，也可以选择本方语言 TTS 播放。

#### 场景 C：客服或销售外呼

用户需要稳定的双向翻译、可配置术语表和固定话术。MVP 阶段只提供基础双向翻译，术语表与话术增强作为后续能力。

## 4. 范围定义

### 4.1 MVP 范围

- macOS 与 Windows 桌面应用。
- 麦克风音频采集。
- 系统输出音频或指定设备音频采集。
- 双向 ASR、翻译、TTS 链路。
- 多语言方向配置，用户可以在客户端自行选择本方语言与对方语言，不将 MVP 限制为固定语言对。
- 音频输入、输出和虚拟设备选择。
- 实时字幕面板。
- 链路状态监控：音量、识别中、翻译中、合成中、延迟、错误状态。
- 基础模型配置：模型路径、后端地址、设备类型、启停控制。
- 基础日志与故障诊断信息。

### 4.2 非 MVP 范围

- 移动端应用。
- 浏览器插件。
- 视频翻译或唇形同步。
- 多人会议中的说话人分离与逐人翻译。
- 复杂术语库、记忆库、行业词典。
- 云端账号体系、计费系统和团队管理。
- 对所有通话软件做深度集成。

## 5. 用户体验需求

### 5.1 主界面

主界面需要包含：

- 当前运行状态：未启动、启动中、运行中、暂停、错误。
- 双向语言方向：本方语言、对方语言。
- 音频链路状态：本方输入、对方输入、本方输出、虚拟麦克风输出。
- 实时字幕区域：原文、译文、时间戳、语音方向。
- 延迟指标：ASR 延迟、翻译延迟、TTS 延迟、端到端延迟。
- 快捷操作：开始、暂停、停止、静音本方翻译、静音对方翻译。

### 5.2 设置界面

设置界面需要包含：

- 麦克风输入设备选择。
- 对方音频捕获设备选择。
- 本机监听输出设备选择。
- 虚拟麦克风输出设备选择。
- 本方语言与对方语言选择。
- ASR、翻译、TTS 模型配置。
- 本地 ASR、TTS 模型路径配置。
- 云端 ASR、翻译、TTS 服务配置。
- TTS 声音、语速、音量配置。
- 是否播放原声、是否播放译音、是否显示字幕。
- 日志级别与诊断信息导出。

### 5.3 状态反馈

- 当音频设备不可用时，UI 应明确提示设备名称和错误类型。
- 当 Python 模型后端未启动或不可连接时，UI 应提示用户启动或重新连接。
- 当模型处理延迟过高时，UI 应显示警告，但不中断通话链路。
- 当虚拟音频设备未配置时，UI 应提供配置说明或引导。

## 6. 功能需求

### 6.1 音频采集

Rust 核心层负责采集音频：

- 支持麦克风输入采集。
- 支持系统音频、应用输出音频或指定设备音频采集。
- 支持 macOS 和 Windows 的平台差异封装。
- 支持音频帧切分、重采样、声道转换和音量归一化。
- 支持 VAD，用于降低无语音片段的模型调用成本。
- 支持回声和串音控制策略，避免 TTS 输出再次进入 ASR 链路。

### 6.2 ASR 语音识别

Python 模型后端负责 ASR：

- 接收 Rust 层传入的音频帧或语音片段。
- 返回增量识别结果和最终识别结果。
- 支持本方语音与对方语音两条独立流。
- 支持语言自动检测或固定语言模式。
- 支持多语言识别能力，用户可在客户端选择识别语言；具体支持语种取决于所加载的本地模型或配置的云端模型。
- 支持结果置信度、起止时间戳和分段 ID。

### 6.3 机器翻译

Python 模型后端负责翻译：

- 根据语音方向选择源语言和目标语言。
- 支持用户在客户端选择源语言与目标语言，不限制为固定语言对。
- 支持短句实时翻译。
- 支持上下文窗口，以改善连续对话翻译质量。
- 返回翻译文本、分段 ID 和处理耗时。
- 保留术语表扩展接口，但 MVP 不实现复杂术语管理。

### 6.4 TTS 语音合成

Python 模型后端负责 TTS：

- 将翻译文本合成为目标语言音频。
- 支持多语言语音合成能力，具体支持语种和音色取决于所加载的本地模型或配置的云端模型。
- 支持配置声音、语速、音量和采样率。
- 支持流式或分段输出音频。
- 返回音频数据、分段 ID、音频时长和处理耗时。

### 6.5 音频输出与路由

Rust 核心层负责输出音频：

- 将对方语音翻译后的本方语言 TTS 输出到本机监听设备。
- 将本方语音翻译后的目标语言 TTS 输出到虚拟麦克风或指定输出设备。
- 支持单独开启或关闭任一方向的 TTS 输出。
- 支持字幕优先模式，即只展示译文，不播放 TTS。
- 支持输出队列调度，避免多个 TTS 片段重叠播放。

### 6.6 实时字幕

Tauri UI 负责展示字幕：

- 显示本方原文、本方译文、对方原文、对方译文。
- 支持按时间顺序滚动。
- 支持区分识别中的临时文本与最终文本。
- 支持复制当前字幕内容。
- 支持清空当前会话字幕。

### 6.7 录音、转写与翻译历史

应用需要支持会话历史能力：

- 支持保存通话录音。
- 支持保存 ASR 转写文本。
- 支持保存翻译文本。
- 支持按会话查看历史记录。
- 支持用户手动删除历史记录。
- 历史保存需要提供显式开关，默认策略应在 UI 中明确展示。

### 6.8 会话控制

- 用户可以启动、暂停、恢复和停止翻译会话。
- 停止会话后需要释放音频设备和模型任务。
- 暂停会话时需要保留配置，但停止音频采集和模型推理。
- 异常恢复后应允许用户重新启动会话。

## 7. 非功能需求

### 7.1 延迟

目标延迟按端到端链路衡量：

- MVP 可接受目标：单向端到端延迟小于 3 秒。
- 优化目标：单向端到端延迟小于 1.5 秒。
- UI 应展示当前链路耗时，便于定位瓶颈。

### 7.2 稳定性

- 会话运行期间不应因单个模型请求失败导致整个应用崩溃。
- 音频设备断开后应展示错误，并允许重新选择设备。
- Python 后端异常退出时，Rust 层和 UI 应进入可恢复状态。

### 7.3 隐私与安全

- 默认优先使用本地模型，不上传音频、识别文本和翻译文本到云端。
- 允许用户主动配置云端模型；启用云端模型时，UI 必须明确展示数据将发送到对应服务。
- 本地日志默认不记录完整音频内容。
- 诊断日志如包含文本内容，需要提供开关。
- 录音、转写和翻译历史默认保存策略必须可配置，用户应能关闭历史保存并删除已有历史。

### 7.4 性能

- Rust 层需保证音频采集与输出线程不被模型推理阻塞。
- Python 后端需支持异步处理或队列处理，避免单个任务阻塞全部链路。
- UI 更新频率需要受控，避免字幕高频刷新导致界面卡顿。

### 7.5 可维护性

- Rust 核心层、Python 模型层、Tauri UI 层之间通过明确协议通信。
- 音频帧、ASR 结果、翻译结果、TTS 音频结果需要统一分段 ID。
- 每个模块应具备独立启动、停止和错误上报能力。

## 8. 技术架构需求

### 8.1 总体架构

```text
通话软件/系统音频
      |
      v
Rust 音频核心层  <---->  Tauri UI
      |
      v
Python 模型后端
      |
      v
ASR -> 翻译 -> TTS
      |
      v
Rust 音频输出/虚拟设备路由
```

### 8.2 Rust 核心层职责

- 管理音频输入输出设备。
- 处理实时音频帧、缓冲区和队列。
- 进行重采样、声道转换、VAD 和基础音频增强。
- 调度 ASR、翻译、TTS 请求。
- 与 Python 后端通信。
- 向 Tauri UI 推送状态、字幕和错误事件。
- 管理虚拟音频设备输出。

### 8.3 Python 模型后端职责

- 提供 ASR、翻译、TTS 服务接口。
- 管理模型加载、卸载和热身。
- 支持本地 ASR、TTS 模型加载。
- 支持云端 ASR、翻译、TTS 服务配置与调用。
- 支持流式或分段式推理。
- 返回结构化结果和耗时指标。
- 暴露健康检查接口。

### 8.4 Tauri UI 职责

- 提供主界面、设置界面和诊断界面。
- 调用 Rust 命令启动、暂停、停止会话。
- 订阅 Rust 层事件，展示实时状态。
- 保存和加载用户配置。
- 展示设备、模型、语言和链路错误。

### 8.5 层间通信

推荐通信方式：

- Tauri UI 与 Rust：使用 Tauri command 和 event。
- Rust 与 Python：优先采用本地 gRPC、WebSocket 或 Unix/Named Pipe 通信。
- 音频数据传输：采用二进制帧，避免频繁 Base64 编解码。
- 状态与控制消息：采用 JSON 或 MessagePack。

基础消息字段：

```text
session_id: 会话 ID
stream_id: audio_local 或 audio_remote
segment_id: 语音分段 ID
direction: local_to_remote 或 remote_to_local
source_lang: 源语言
target_lang: 目标语言
timestamp_ms: 时间戳
payload: 音频或文本负载
latency_ms: 处理耗时
```

## 9. 平台要求

### 9.1 macOS

- 支持麦克风权限申请与状态提示。
- 支持系统音频捕获方案评估。
- 支持虚拟音频设备配置说明，例如 BlackHole、Loopback 或等价方案。
- MVP 阶段不内置 macOS 虚拟音频驱动。
- 需要处理 Apple Silicon 与 Intel Mac 的模型运行差异。

### 9.2 Windows

- 支持 WASAPI 音频输入输出。
- 支持系统回放设备捕获。
- 支持虚拟音频设备配置说明，例如 VB-CABLE 或等价方案。
- MVP 阶段不内置 Windows 虚拟音频驱动。
- 需要处理独占模式、共享模式和采样率不匹配问题。

- 本方语言。
- 对方语言。
- 麦克风输入设备 ID。
- 对方音频捕获设备 ID。
- 本机监听输出设备 ID。

- ASR 模型配置。
- 翻译模型配置。
- TTS 模型配置。
- TTS 声音、语速、音量。
- 是否启用本方到对方翻译。

- 是否显示字幕。
- 是否播放 TTS。
- 是否保存录音。

- 是否保存翻译文本。

## 11. 错误与诊断需求

### 11.1 错误类型

- 音频设备不可用。
- 麦克风权限未授权。
- 系统音频捕获失败。
- 虚拟音频设备未配置。
- Python 后端不可连接。
- 模型加载失败。
- ASR 请求失败。
- 翻译请求失败。
- TTS 请求失败。
- 输出队列阻塞或延迟过高。

### 11.2 诊断信息

诊断界面应展示：

- 当前应用版本。
- 操作系统版本。
- 可用音频设备列表。
- Python 后端连接状态。
- 模型加载状态。
- 当前模型来源：本地模型或云端模型。
- 最近错误日志。
- 最近一次端到端链路耗时。

## 14. 风险与待确认问题

### 14.1 主要风险

- 系统音频捕获和虚拟音频路由在 macOS 与 Windows 上差异较大。
- 本地 ASR、翻译、TTS 模型可能造成较高延迟或资源占用。
- 云端模型会引入网络延迟、可用性和隐私提示要求。
- TTS 输出可能被本方 ASR 再次捕获，导致翻译回环。
- 双向同时说话时，分段、队列和播放策略会影响自然度。
- 通话软件的音频设备配置对普通用户可能较复杂。

### 14.2 已确认产品决策

- 语言方向不限制为 `中文 <-> 英文`，用户可以在客户端选择本方语言与对方语言；实际可用语种由模型能力决定。
- ASR 和 TTS 需要支持加载本地模型，也需要支持配置云端模型。
- MVP 阶段不内置虚拟音频驱动，仅提供第三方虚拟音频设备配置说明。
- 需要支持录音、转写和翻译历史保存能力。
- 不针对特定通话软件做专用对接，目标是通过系统音频与虚拟音频设备让电脑上的通话软件通用可用。
